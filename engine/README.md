# 规则引擎

`server.py` 是单文件、仅 Python 标准库的 MCP stdio 服务器。支持 Python 3.10+、POSIX 本地文件系统（使用 `fcntl.flock`、`O_NOFOLLOW` 和目录 fd）；本机验证环境为 Python 3.12.3。规则依据为 `../docs/rules.md`。14 个 AGT MCP 资源（`ww-lead`、`ww-god`、`ww-p01` … `ww-p12`）由 `scripts/setup-team.sh` 按本机路径生成。

## 启动与当前局

每局由 lead 实例（`WW_SEAT=lead`）的 `new_game` 开局：它取 `games/` 下最小的未用编号 `gNNN`，建 0700 目录，写入 `seats.json`（每个座位的模型和成员 ID `<局>-god`、`<局>-p01` …），再把相对符号链接 `games/current` 原子地切到新对局。当前对局已开局但未完局时拒绝，除非传 `abandon_current: true`；旧对局的目录原样保留。lead 实例只有这一个工具，不能读取或改动对局。

手动启动一个实例（在仓库根目录）：

```bash
WW_SEAT=god python3 engine/server.py
```

其他进程用同一命令，把 `WW_SEAT` 改为 `lead` 或 `p01` 至 `p12`。缺失、空值或其他值会向 stderr 报错并以状态码 2 退出。进程启动时锁定身份，之后不重新读取环境；工具参数没有身份、角色、令牌或代理执行入口。`target` 只是动作对象，不能改变动作提交者。上帝实例不提供玩家工具，直接猜名称调用也会被拒绝。

MCP 采用每行一条 UTF-8 JSON-RPC 2.0 消息；stdout 只输出协议数据。支持 `initialize`、`notifications/initialized`、`ping`、`tools/list`、`tools/call`；不提供读取原始文件的 MCP resource。初始化兼容 2024-11-05、2025-03-26、2025-06-18 协议版本。调用示例（经 MCP 客户端发送）：

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"start_game","arguments":{"seed":20261019001}}}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"next_step","arguments":{}}}
```

种子写入审计记录，并确定角色及随机发言顺序。正式对局建议由运维生成不可预测的种子；不要将种子发给玩家。所有动作参数均必填；空刀、空守、弃票、不射击、撕徽使用 JSON `null`，女巫不用药为 `{"mode":"pass","target":null}`。

环境变量：

| 变量 | 含义 |
| --- | --- |
| `WW_SEAT` | 必填，唯一身份源：`lead`、`god` 或 `p01`…`p12` |
| `WW_GAMES_DIR` | 可选，默认脚本上级仓库的 `games`；测试用临时目录 |
| `WW_CONVERSATIONS` | 可选，JSON 对象；部署会话映射，默认 `{}`，不保存游戏状态 |

`WW_CONVERSATIONS` 的合法键为 `public`、`wolves`、`private:p01`…`private:p12`，值为实际 AGT conversation id。只有上帝的 `next_step()` 使用映射；没有配置时返回真实逻辑目标及 `conversation_id:null, mapping_required:true`。投票时始终返回单个 `target:"public"` 指令，`actors`、`voters` 都是本轮完整有效选民座位列表（`mentions` 是它们对应的成员 ID）；上帝在公共群一次性 @ 全部这些座位，提示玩家仅通过 `vote` 工具秘密提交、群里只回复“已投票”。列表不会随部分投票缩减；缺失公共群映射也不会退化为私聊或伪造 ID。每个指令的 `mentions` 是要点名的成员：`actors` 中的座位按当局 `seats.json` 里的 `seats.pXX.principal` 换成 agt 成员 ID（如 `g001-p03`；没写的座位原样返回），上帝发消息时原样填进 mentions。映射改动后重启上帝 MCP 进程即可，日志中的游戏状态不受影响。

## 工具契约

查询返回 MCP text 内容中的 JSON；成功提交统一返回 `{"accepted":true}`，不附带事件序号、隐私状态或投票进度。非法操作返回 `isError:true`，不追加事件。发言/遗言/笔记文本长度为 1–20000 个字符。

| 工具 | 权限、阶段及输入 | 输出/效果 |
| --- | --- | --- |
| `my_info()` | 双方，无输入，须已开局 | 公共历史、公开存活名单、警长、胜负；玩家另见本人身份/笔记/可用动作/简要打法；上帝另见角色表 |
| `start_game(seed)` | 仅上帝，空局；整数种子 | 洗牌 4 狼 4 民及预女猎守各一，进入首夜 |
| `next_step()` | 仅上帝 | 阶段、应点名座位、会话目标/实际映射、允许操作、主持指令；空局提示初始化；票齐后含完整票型/权重/计数 |
| `advance()` | 仅上帝，死讯公布或全票结果阶段 | 公布死讯/票型并自动结算；不能跳过玩家行动或替投 |
| `export_replay()` | 仅上帝，完局后 | 格式版本、当局名、胜方、角色表、完整 `events` 和原字节对应 `jsonl` |
| `guard(target)` | 存活守卫，守卫阶段 | 存活目标或 null；禁止连续两夜同一非空目标 |
| `wolf_kill(target)` | 存活狼人，狼队阶段 | 存活目标或 null；队内协商后任一存活狼人提交，首次合法提交生效 |
| `witch(mode,target)` | 存活女巫，女巫阶段 | `pass/save/poison` 三选一；只有 poison 填存活目标，save 使用本夜刀口；校验药量及不能自救 |
| `inspect(target)` | 存活预言家，预言家阶段 | 查验存活目标；结果只进入预言家 `my_info().inspections`，只有 good/wolf |
| `sheriff_join(join)` | 首日警选，尚未应答的玩家；bool | 上警/不上警，全部应答后自动定候选人或结束警选 |
| `withdraw(withdraw)` | 警上发言结束后，每名原候选人一次；bool | 退水/留下；退水者既不能投票也不能被投 |
| `speak(text)` | 白天当前轮到的存活发言者 | 记录公共发言并推进队列；警长最后一次发言同时包含归票，无强制绑定放逐目标 |
| `choose_order(direction)` | 存活警长，每日正式发言前 | `left/right`，安排警长末位的循环发言队列 |
| `vote(target)` | 当前合格选民，每轮一次 | 候选人或 null 弃票；提交保密，票齐后才能结算 |
| `last_words(text)` | 当前遗言队列指定的死者 | 首夜死亡或白天放逐的遗言；其余死者不能自行提交 |
| `shoot(target)` | 当前死亡后队列的猎人 | 刀死/放逐才可开枪；毒死禁用；存活目标或 null；仅一次 |
| `badge(target)` | 当前死亡后队列的原警长 | 移交给存活者或 null 撕毁 |
| `explode()` | 白天发言阶段，轮到自己且仍存活的狼人 | 自爆出局，无遗言；警选自爆使警徽永久流失 |
| `note(text)` | 仅玩家，包括死亡/完局后 | 追加本人的私密笔记；其他玩家及上帝日常查询均看不到 |

所有目标仅接受 `p01`…`p12`；所有 JSON schema 都拒绝额外字段，运行时再次验证类型、身份、阶段、存活、次数和目标。玩家工具列表不随身份角色改变，避免通过列表泄露角色；合法动作由 `my_info` 给本人提供。投票中已投玩家仍看到同样的 vote 操作提示，以免通过查询观察进度；再次提交会被拒绝且不会改票。

狼人额外看到完整狼队座位（包括已死亡队友）；女巫只有解药尚在且轮到当晚女巫行动时看到刀口；守卫看到上次守护；预言家看到自己的历次查验。普通玩家、其他神职不能获取这些私密字段。玩家完局后仍不能通过引擎读取他人身份或完整日志。

## 已实现规则与需明确的补充约定

明确规则均按 `docs/rules.md` 实现：固定板子和种子分配；守→狼→女巫→预言家；空守/自守/不连守、空刀；女巫两瓶药各一次且每夜至多一瓶、全程不可自救；同守同救死亡；首日先警选后死讯；竞选退水/PK、全员上警无选民/无人上警无警徽、单候选自动当选；首夜及放逐遗言、之后夜死无遗言；警长定方向且末位归票、1.5 票、死亡移交/撕徽；放逐平票 PK 后其他人重投、再平当天不出人；猎人毒死禁枪；轮到狼自己发言才可自爆；杀光民或神的屠边及全狼出局判胜。

2026-10-19 用户批准的四项补充及其余待确认细节已写入 `docs/rules.md` 对应章节。以下第 1 项、第 2 项的同夜统一结算、第 3 项、第 4 项的保留首夜死亡动作已获批准；其他算法和细节仍标为实现补充约定，不视为用户另行批准：

1. **首夜待公布死者参加警选**：首夜动作结束产生待结算死者，警选期间所有人仍可报名、发言、投票、当选；上帝公布死讯时死亡生效并判胜。当选的待死者随后处理移徽。这样不会由选民/候选资格提前暴露死讯。
2. **同夜多死与立即判胜**：刀/毒本夜统一生效，再立即判胜；避免处理顺序改变同夜结果。同一人既中刀又中毒时，毒优先，猎人不能开枪；毒不受守护或解药保护。若同批最后狼人和最后民/神同时死，先按“所有狼出局”判好人胜；死因优先和同批双边胜利的优先级仍为待确认细节。
3. **终局优先级**：任意死亡结算触发胜负后立即终局，不再执行开枪、遗言、移徽或下一个夜晚。包括最后一个民白天被放逐，以及猎人开枪打死最后一狼。此优先级已获用户批准，测试显式固定此行为。
4. **警选自爆**：记录自爆及警徽流失，先公开昨夜死者；自爆者与待公布夜死统一结算并判胜。未终局则保留首夜死者遗言和合法猎枪，处理完死亡动作后直接入夜，不恢复警选或白天投票。枪击造成死亡时立即再判胜，终局清空剩余队列。自爆者无遗言；若自爆者也是待公布夜死，仅死亡一次，按自爆处理。自爆与夜死合并判胜、重合死因优先仍是待确认细节。普通阶段自爆的警长仍先处理移徽。
5. **死亡后动作次序**：夜死按座位升序，为每个死者依次排猎人开枪→警徽→遗言；开枪造成的新死者的必要移徽追加在现有队列后。被枪带走无额外遗言，因为原文仅授予首夜死亡及放逐遗言。
6. **投票细节**：每轮不可改票、无超时自动弃票或上帝代投；允许自投；全弃票/无有效票视为无人当选或无人放逐，不产生全员 PK。放逐 PK 排除 PK 当事人；警选 PK 仍仅原不上警者投票，退水者不得重新投票。退水后仅剩一名候选人自动当选。全部玩家操作都必须收到合法提交，离线时主持只能重试通知。
7. **方向/随机细节**：警左按座号递增，警右递减；无警长且多名夜死时取最小座号死者为起点，寻找其后首个存活者；没有死者时由已记录种子决定起点。警上发言从种子决定的随机候选人起，按座号递增循环。PK 发言按座号递增。
8. **技能未规定的目标细节**：查验可自验，不能验已公布死亡者；狼可刀自身或队友。狼队讨论不由引擎自然语言判断，队内先协商，再由任一存活狼人提交统一刀口，后续重复提交无效。
9. **笔记与导出**：笔记始终只通过本人身份提交/查询，但作为完整审计事件，会包含在上帝完局导出中。警徽流只记录在玩家自愿发言里，不自动安排查验或移徽。

## 存储、并发与保密边界

唯一事实来源为 `games/current/events.jsonl`；没有状态快照、状态数据库或第二份可变状态文件。每个请求在 `games/.engine.lock` 的排他锁内重新读取并校验完整日志，再确定性重放；合法变更追加一条命令事件，自动结算是同一事件的确定性结果。锁文件只是同步对象，不含游戏状态，不得在运行中删除/替换。

每条事件包含 `version, seq, at, actor, action, args, prev, hash`。序号连续，SHA-256 链绑定前一事件和本条完整内容；文件以 `0600` 创建，追加后 `fsync` 文件和目录。原始日志包含所有夜间动作、查验目标、票型和笔记，只能由上帝在完局后通过 `export_replay` 取得。种子足以重建角色分配，导出另附明文角色表，便于回放。

投票未齐时 `my_info/next_step` 对任何其他投票提交的可见输出保持不变，不包含已投名单、部分票型、剩余票数或事件序号。主持按单个公共群指令一次性提及完整选民集合，玩家通过 `vote` 工具提交并在群聊回复 `[[silent]]`。票齐后 `next_step` 仅向上帝返回全票；`advance` 将票型记入公共历史，之后所有人可读。

安全限制：

- `current` 必须是指向 games **直接子目录**的相对符号链接；拒绝绝对路径、路径穿越、目录代替链接以及目标目录再次为符号链接。日志拒绝符号链接、硬链接、非普通文件和开放给组/其他用户的权限；FIFO 不会阻塞读请求。
- 写入前再校验 current 目标名称/目录 inode 和日志长度。所有进程共享相同的根锁，因此跨进程投票/笔记不会交错或丢失。
- 运行中换局也必须持有 `.engine.lock`，用原子 rename 替换 current；或者先停掉全部 13 个进程再换局。不能用不遵循锁的外部命令边运行边改链接。
- 非法动作不会落盘。序号/哈希/语义错误、截断尾行均拒绝重放及追加，不自动截断或“修复”审计证据。发生写入/同步故障时不返回成功；可能已经写入完整或部分事件，需停机由运维核对日志。不要盲目重试笔记，避免提交结果不确定时产生重复记录。
- 哈希链用于发现破坏，无法抵抗有宿主文件写权限的人重新计算整条链，也无法单凭日志发现整个有效尾部被外部删除。玩家的权限边界是固定 MCP 资源：不得同时给予读 `games/` 的 shell/文件工具、环境修改或启动其他身份服务器的能力。同一 Unix UID 下不能仅靠环境变量获得 OS 隔离。

验证导出可把返回的 `jsonl` 原样写入隔离当局目录的 `events.jsonl`（权限 `0600`），让 current 指向该目录，然后启动同一服务器；任何查询都会完整校验并重放。不要向玩家分发导出。

## 注册到 AGT

`scripts/setup-team.sh` 为 lead 和每个座位注册一个 MCP 资源，启动参数相同，只有 `WW_SEAT` 不同（`lead`、`god`、`p01` … `p12`）：

```json
{
  "type": "stdio",
  "command": "python3",
  "args": ["<仓库>/engine/server.py"],
  "cwd": "<仓库>",
  "env": {
    "WW_SEAT": "god",
    "WW_GAMES_DIR": "<仓库>/games",
    "WW_CONVERSATIONS": "{}"
  }
}
```

`WW_CONVERSATIONS` 由 lead 在开局时填上公共群 ID；狼队群由上帝在对局中用 `remember_conversation` 记下。lead 实例只有 new_game；上帝实例没有玩家动作，玩家实例没有 start_game、advance、next_step 和 export_replay。

## 契约测试

```bash
# 在仓库根目录
python3 -m unittest discover -s engine/tests -v
```

测试使用临时 games 目录，不创建真实对局。覆盖夜间技能、警选/退水/PK、秘密投票、猎人/遗言/警徽、自爆、两种屠边及全狼出局、完整导出重放；隔离测试实际启动全部 13 个不同 WW_SEAT 的 stdio 进程，检验字段及越权拒绝。并发测试启动 12 个玩家进程同时提交 96 条笔记，再并发投票，另起相同座位进程争抢重复投票，验证恰好 12 张有效票、连续事件序号和完整重放。另验证日志损坏、截断、特殊文件/符号链接、不安全权限、写入失败和部分写入后拒绝继续。

服务器版本为 `1.2.0`（新增 lead 实例和 new_game）；旧版本含警选自爆的日志可能与新死亡动作队列不兼容，不能直接用于续局或重放，须保留原版本回放旧局。事件封装格式仍为 v1。
